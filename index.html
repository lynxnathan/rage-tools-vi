    Rage Tools VI¶

    Reverse engineering of GTA VI / Leonida RPF9 archives, with the long-term goal of enumerating every stored entry and decoding the bytes behind it.

    Documentation map

    This site is the navigable model of the project. The append-only research record is investigation.md and the live check/todo list is plan.md at the repository root. The diagrams below are the UML/system view that ties those files together.

    First milestone — met¶

    One decoded record independently predicts the exact byte range of a payload that has already been checksum-verified.

    The core_bvh4 descriptor is that record. A decoded 208-byte descriptor carries the entry's exact payload size at +0xa0, pairs with the immediately following stream, and that stream's decoded bytes beyond the declared size are zero — verified on 260 re-decoded samples. Applied across the archive, it yields 188,298 entries across 14 archives, whose boundaries are payload-derived and whose count matches the declared index in 1,253 of 1,261 core_bvh4 packs.

    New here? Start with From first principles. The result list is in Findings.

    Repository conventions¶

    • Offsets are absolute archive offsets.
    • Ranges are start-inclusive and end-exclusive.
    • *.rpf samples and output/ are local and untracked.
    • plan.md is the live check/todo list; investigation.md is the append-only research record.
    • Handoff artifacts live under handoff/.

    Sibling: the GPU layer¶

    The archive work stops at stored bytes. What the GPU does with them is a separate project, kept in its own repository and included here as a submodule:

    Path What it does
    rdna2-spirv/ Generic AMD RDNA2 (GFX10.x) decompiler — machine code to SPIR-V, with decoder agreement against LLVM, golden buffer tests, and exact pixel tests on a software Vulkan backend

    Its method, evidence, and open gaps are recorded there, in its own plan.md and investigation.md. Clone with --recurse-submodules to get it.
